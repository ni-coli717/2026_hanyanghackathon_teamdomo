# Claude Code 작업 지시: 냄새 나침반 — AI 예측 모델 + 공기질 관리 모듈 통합

현재 저장소의 Streamlit 앱(주민용 확인 앱 '냄새 나침반', 측정 앱 '냄새 기록', 비공개 운영자 앱)에 **3개월 관측 데이터**, **학습 완료된 악취 예측 모델**, **Arduino 공기질 관리 모듈**을 통합한다. 계획만 쓰지 말고 저장소를 먼저 분석한 뒤 구현·실행·검증까지 완료한다.

작업은 4단계다. 앞 단계가 화면에서 동작하는 것을 확인한 뒤 다음으로 넘어간다.

---

## 0. 먼저 확인할 것

- 저장소 구조, 진입 파일, 데이터 저장 계층(repo/service), 현재 지도·나침반·시간 슬라이더 구현, 시연 데이터 로딩 경로, `st.secrets`·환경변수 사용 방식.
- 기존 사용자 변경(지도 중심 UI, 네이버지도식 짧은 용어, 두 앱 분리)은 **보존한다**. 이번 작업은 "데이터 교체 + 모델 연결 + 예보 추가 + 기기 연동"이며 UI 구조를 다시 갈아엎지 않는다.

### 전체 역할 분리 (모든 단계에서 유지)

1. **모델**은 구역별 유입 가능성 `level`(낮음/보통/높음)만 추정한다.
2. **제어 규칙**(`AutoRule`)이 `level` 이력을 보고 ON/OFF를 결정한다. 모델이 직접 기기를 켜지 않는다.
3. **보드**는 받은 ACTION만 수행한다. 보드가 풍향을 보고 스스로 판단하지 않는다.
4. 모델 파일이 없어도, 기기가 없어도 앱은 죽지 않고 각각 "추정 보류", "연결된 기기 없음"으로 표시한다. 가짜 성공을 만들지 않는다.

## 1단계 — 데이터 교체와 모델 배치

### 1-1. 패키지 배치
- `odor_model/`을 저장소 안 `src/model/` 또는 기존 구조에 맞는 위치로 옮기고 import 경로를 정리한다. `features.py`, `train.py`, `predict.py`, `device_service.py`, `artifacts/odor_model.joblib`, `artifacts/candidates.csv`, `artifacts/evaluation.md`, `sample_forecast.csv`를 모두 포함한다.
- `requirements.txt`에 `scikit-learn`, `joblib`, `openpyxl`, `requests`, `pyserial`을 추가한다.
- joblib 로딩이 실패해도 앱이 죽지 말고 "모델 없음 → 추정 보류"로 동작해야 한다.
- `predict.predict_rows(weather_df, model)`를 공통 서비스 함수 하나로 감싼다: `analysis_service.predict_windows(weather_df) -> DataFrame`. 지도·나침반·공기질 관리·운영자 화면이 전부 이 함수 결과만 사용한다. 화면마다 따로 계산하지 않는다.

### 1-2. 데이터 교체
- 시연 데이터를 8일치에서 `운양동_악취관측_20260618_20260916.xlsx`로 교체한다. 시트: 관측데이터(7,143건), 시간창집계(364창), 기상스냅샷(1,092건), 코드북.
- `weather_basis`를 화면에 구분 표시: `observed_public_reference`→"관측", `estimated_from_adjacent_actuals`→"추정", `synthetic_climatology`→"시연". `record_origin=simulated`는 자료 정보 화면에 표시한다.
- 시간 슬라이더의 시각 목록은 시간창집계의 `window_start`(6/18 07:30 ~ 9/16 22:00, 364개)를 사용한다. 없는 시각을 만들지 않는다.
- 구역 대표점·후보 좌표는 `features.DEFAULT_GEO`를 초기값으로 쓰되, 저장소에 좌표 설정 파일이 있으면 그것을 `geo.json`으로 넘겨 우선한다. 후보는 지역·시설 유형 수준 이름만 쓴다.

**1단계 확인:** 슬라이더가 364개 시각으로 늘어나고, 과거 시각 선택 시 그 시각의 관측 집계가 지도에 뜬다.

## 2단계 — 지도·나침반에 모델 연결

### 2-1. 지도 (냄새 유입 화살표)
- 선택 시각의 기상(427 양촌)을 `predict_windows`에 넣어 3개 구역 결과를 받는다.
- 흐름선은 구역 대표점 주변에서 `move_to_deg` 방향으로 그린다. 반복 화살표 머리는 기존 구현 유지.
- 색은 `type_top`: 축산계 추정 `#D97706`, 하수계 추정 `#7C3AED`, 기타/미확인 `#64748B`. 선 굵기·불투명도는 `level`로.
- 표시 규칙:
  - `level=낮음`이고 그 시간창의 실제 관측 감지율도 25% 미만이면 유색 악취 화살표를 그리지 않고 중립 회색 "바람 이동" 레이어만.
  - `direction_status=방향 보류(약풍)`이면 화살표를 그리지 않고 구역 마커에 "방향 보류" 배지.
  - `status=추정 보류`(기상 결측)이면 "자료 없음".
- 흐름선 클릭 시 상세: 유입 방위, 이동 방위, 유형, 정렬 후보(`aligned_candidates`), 기준 시각, 자료 구분, "예비 실험" 배지.
- **구역 마커 색 = 실제 관측 감지율**(관측 부족/감지 낮음/일부/집단), **화살표 = 모델 추정**으로 역할을 분리하고 범례에 명시한다.

### 2-2. 나침반
- 지도와 동일한 `predict_windows` 결과를 사용한다. 선택 위치가 속한 구역의 `wind_from_deg`를 강조 바늘로, 문구는 "동북동쪽에서 유입 추정".
- `여러 방향 가능`이면 문구 그대로, `방향 보류(약풍)`이면 바늘 비활성 + "방향 보류". `level`은 상태 배지("유입 가능성 높음/보통/낮음"). **p 숫자와 % 표기는 하지 않는다.**
- 359°→1° 회전 시 최단 각도로 보간한다.

**2단계 확인 (실제 데이터로 검증):**
- 2026-09-11 22:00 (동남동 0.2 m/s, 집단 감지) → 마커 "집단 감지", 화살표 숨김, 나침반 바늘 비활성
- 2026-09-15 22:00 (동북동 0.5 m/s, 집단 감지) → 화살표 서남서(247.5°), 나침반 동북동 강조, 축산계 주황
- 2026-09-14 12:30 (서북서 3.0 m/s, 감지 0건) → 유색 화살표 없음, 회색 바람 레이어만

## 3단계 — 예보 모드

- 시간 슬라이더의 "최신" 이후를 예보 구간으로 확장한다. 출처 우선순위:
  1. `st.secrets["kma"]["service_key"]`가 있으면 `predict.fetch_kma_forecast(key, nx, ny)` 호출(nx/ny는 secrets, 기본 55/128, 운영자 확인 필요). 결과 캐시 TTL 1시간, 발표 시각 표시.
  2. 키가 없거나 실패하면 `sample_forecast.csv`로 채우되 반드시 "시연 예보"로 표시한다. 실패를 조용히 숨기지 않는다.
- 예보 구간은 `basis=kma_forecast`/`forecast_csv`로 구분해 "예보 기준"이라 표시하고, 과거 관측 구간과 스타일을 섞지 않는다(예: 예보는 점선).
- 미래 구간을 "실시간"이라고 표시하지 않는다.

**3단계 확인:** 최신 이후 구간 선택 시 "예보 기준"/"시연 예보" 배지와 점선 스타일이 과거 구간과 구분된다.

## 4단계 — 공기질 관리 모듈(Arduino) 연동

첨부: `arduino/odor_purifier/odor_purifier.ino`(보드에 업로드 완료된 스케치), `odor_model/device_service.py`.

### 4-1. 통신 프로토콜
Python → Arduino (1줄):
```
ODOR|<WIND>|<LEVEL>|<ACTION>|<BASIS>
  WIND   N NNE NE ENE E ESE SE SSE S SSW SW WSW W WNW NW NNW / CALM / NA
  LEVEL  LOW MID HIGH HOLD        HOLD = 자료 없음·추정 보류
  ACTION ON OFF HOLD              HOLD = 직전 상태 유지
  BASIS  OBS EST DEMO FCST
PING                              5초 주기 하트비트
MODE|AUTO                         수동 모드 해제
```
Arduino → Python:
```
ACK|<LEVEL>|<ACTION>|<MODE>       MODE = AUTO / MANUAL
OVERRIDE|ON  /  OVERRIDE|OFF      버튼 짧게 누름(수동 토글)
REPORT|SMELL                      버튼 길게 누름(주민 '냄새 남' 신고)
```

### 4-2. 웹앱 통합
- `DeviceLink`는 `@st.cache_resource`로 **한 번만** 생성한다. 재실행마다 새로 열면 포트가 잠긴다.
- `AutoRule`은 `st.session_state`에 보관한다(상태 기계이므로 초기화되면 안 된다).
- 선택 시각이 바뀔 때마다 등록 구역의 예측 한 행을 `push_prediction(link, rule, pred_row, basis_key)`에 넘기고, 반환된 `action`·`mode`·`device_fan`을 화면에 표시한다.
- `REPORT|SMELL` 수신 시 측정 앱과 같은 저장 경로로 관측 1건을 기록한다: `collection_mode="spontaneous"`, `record_origin="device_button"`, `odor_detected=true`, `intensity` 없음, `zone_id`는 등록 구역. **정기 관측 감지율의 분모·분자에 넣지 않는다.**

### 4-3. 공기질 관리 패널
```
공기질 관리
등록 위치      운양동 중앙
주변 상태      유입 가능성 높음 · 예보 기준        ← 모델
자동 대응      사용 중 / 사용 안 함               ← 토글
기기 상태      연결됨 · 가동 중 / 대기 중          ← 보드가 ACK로 보고한 실제 값
                또는 연결된 기기 없음 / 연결 끊김
포트           [자동 감지] [연결] [해제]
```
- 기기 상태는 **웹앱이 보낸 명령이 아니라 `ACK`로 돌아온 값**을 표시한다.
- `mode=MANUAL`이면 "수동 조작 중 · 자동 대응 일시 중지" + [자동으로 되돌리기](`link.set_auto()`).
- `action=HOLD`(자료 없음)는 "판단 보류"로 표시한다. "냄새 없음"으로 바꾸지 않는다.

**4단계 확인:**
- 2026-09-14 12:30 → `ODOR|WNW|LOW|OFF|DEMO` → 빨간 LED, 팬 정지, LCD `AIRFLOW: WNW / SYSTEM: STANDBY`
- 2026-09-15 22:00 → 높음 2회 연속 시 `ODOR|ENE|HIGH|ON|DEMO` → 초록 LED, 팬 회전, LCD `ODOR INFLOW EST / PURIFYING AIR...`
- 버튼 길게 → `REPORT|SMELL` → 지도에 자발 제보 1건 반영, 정기 감지율은 불변, LCD `REPORT SENT`
- USB 분리 → 15초 뒤 LCD `NO SIGNAL`, 팬 정지, 웹앱 "연결 끊김"

## 5. 운영자 화면

- `artifacts/evaluation.md`를 그대로 렌더링(평가표, 혼동행렬, 계수).
- "모델 재학습": `train.py`를 현재 데이터로 실행해 새 joblib을 **별도 파일로** 저장하고 기존 평가와 구분해 표시한다. 재학습 모델은 운영자가 명시적으로 선택할 때만 주민 화면에 반영된다.
- 노출할 설정: 임계값(0.5/0.75), 약풍 기준(0.5 m/s), 정렬도 최소(0.5), `on_streak`/`off_streak`, 포트, 마지막 ACK, 마지막 오류, 전송 로그. 모두 "운영 설정·공인 기준 아님" 표시.
- 후보 좌표·구역 대표점 편집과 "임시 좌표" 표시.

## 6. 지켜야 할 표현

- 모든 모델 결과에 "예비 실험·미보정" 배지(작게, 상시). 확률 %, "정확도 XX%"를 주민 화면에 쓰지 않는다.
- 유형·정렬 후보는 "추정"이며 발생원 판정이 아니다. 첫 화면에는 방향만, 후보 지역명은 상세에서만, 시설명은 쓰지 않는다.
- "자료 없음"·"자료 부족"·"방향 보류"·"냄새 없음"을 서로 다른 상태로 유지한다.
- 용어는 기존 네이버지도식 짧은 이름을 유지한다.

## 7. 최종 완료 기준

- 모델 파일을 지운 상태에서도 앱이 죽지 않고 "추정 보류"로 뜬다.
- 기기 없이 실행해도 "연결된 기기 없음"으로 뜬다.
- 2·3·4단계 확인 항목이 실제 실행 화면에서 모두 재현된다.
- 보드 버튼으로 끄면 웹앱이 `MANUAL`을 인식하고, 이후 자동 명령이 보드를 덮어쓰지 않는다.
- 데스크톱 1440×900, 모바일 390×844에서 확인. 화면 캡처와 LCD 사진 첨부.
- 변경 파일 목록, 실행 방법, 필요한 secrets(`kma.service_key`, `kma.nx`, `kma.ny`), 미완료 항목을 짧게 보고.
